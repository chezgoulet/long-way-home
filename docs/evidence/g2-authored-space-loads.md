# Evidence: an authored space loads, and navigation bakes itself

Gate G2's authoring bar, Track B's last unproven link. Recorded from a headless run on the
playtest host, not from reasoning about the code.

## What was proven

A map generated by `tools/mapgen/mapgen.py` -- geometry, a light, a player start, and fifteen
`waypoint` entities -- compiles, packs, loads in the engine, spawns the player, renders, and
causes the engine to bake `maps/<map>.nav` navigation data from those waypoints. The whole
chain is closed: author -> compile -> pack -> load -> navigate.

## The two commands are not interchangeable

`map <name>` takes the **single-player** route: the bridge intercepts it and loads the SP game
module. `spmap <name>` takes the **Holomatch** route, which wants `maps/<name>.aas` bot data and
dies with `Fatal: can't open maps/<map>.aas`. The SP route is the one to use for authored space.

## Three silent faults, and why the checks missed them

The first compile of the room exited 0 and reported "zero shader misses" while producing a BSP
whose brush, shader and surface lumps were all **empty**. The engine then rejected it with
`ERROR: Map with no shaders`. Three faults stacked, each invisible at the point of failure:

1. **Inverted brush winding.** A brush face's three points must be ordered so the computed
   normal points *into* the brush from that face, matching Raven's own maps. Ordered the other
   way every brush is inside-out, and q3map2 discards it **without a warning** and still exits 0.
2. **`-fs_basepath` pointing at the install directory.** q3map2 looks for a child directory
   spelled exactly `baseEF`; the installation spells it `BaseEF`. On a case-sensitive filesystem
   that never matches, so no asset resolves -- a second zero-exit failure.
3. **A verification that could not see either.** The check was the compiler's exit code plus a
   grep for "not found"; q3map2's actual message is `Couldn't find image for shader ...`, which
   that pattern never matched. The bounding box in the log was the tell -- `Size: 340282346638...
   to -340282346638...`, i.e. uninitialized float extremes, meaning zero brushes had been parsed.

Also caught before shipping: the room was initially built from `common/caulk`, the invisible
structural material, so it would have loaded and rendered as a void.

## The check that replaces the failed one

`tools/mapgen/check-bsp.py` reads the compiled BSP and requires non-empty **shaders**, **brushes**
and **surfaces** lumps, exiting non-zero otherwise. It is wired into the build script, so the
pipeline now fails on the defect instead of exiting green and letting the game discover it.

```
maps/testroom.bsp     OK     (4/17 lumps empty)
```

The four empty lumps -- fogs, lightmaps, lightgrid, visibility -- are expected: they need a
lighting/visibility pass, which a test space does not run.
